# Zoo Zoo Club — 참고작 시스템 분석과 설계

작성일: 2026-10-07

## 1. 분석 방법과 한계

참고작은 「고양이와 스프: 말랑 타운」(개발 아름게임즈, 퍼블리싱 네오위즈, 2024년 5월 국내 출시)이다. 이 문서의 분석은 스토어 설명, 인앱 구입 목록, 사용자 리뷰, 출시 기사처럼 공개된 자료만 근거로 했다. 앱을 분해하거나 내부 데이터를 추출하지 않았고, 앞으로도 그렇게 하지 않는다.

따라서 아래 내용은 세 등급으로 나뉜다. "확인됨"은 공개 자료에 직접 적혀 있는 내용이고, "추정"은 공개 자료와 장르 관례로부터 미루어 본 내용이며, "자체 설계"는 Zoo Zoo Club을 위해 새로 정한 내용이다. 성장 시간, 가격, 보상량 같은 수치는 공개 자료에 없으므로 이 문서와 코드의 수치는 전부 자체 설계한 임시 값이다. 실제로 플레이하면서 수치를 기록해 주면 그 관찰을 반영해 밸런스를 다시 잡을 수 있다.

Zoo Zoo Club은 장르와 시스템 구조만 참고하고, 이름·캐릭터·세계관·아트는 모두 새로 만든다.

## 3. 구조 분석

### 3.1 코어 루프

이 장르의 뼈대는 시간이 걸리는 생산 사슬과, 그 산출물을 요구하는 주문이다.

```
씨앗 심기 → (대기) → 수확 → 생산 시설에 투입 → (대기) → 완성품 수거
     ↑                                                      ↓
  코인·경험치 ←──────────── 주문/배송 납품 ←──────────── 창고
     ↓
  새 작물·시설·장식 해금, 마을 확장 → 더 긴 생산 사슬
```

플레이어는 한 번 접속해서 수확·투입·납품을 몰아서 하고, 타이머가 도는 동안 자리를 비운다. 꺼 둔 동안에도 시간이 흐르는 것이 핵심이라, 진행 상태를 "남은 시간"이 아니라 "시작 시각"으로 저장해야 한다.

### 3.2 경제

재화는 코인(게임 내 획득)과 보석(유료)의 이중 구조다(확인됨). 코인은 주문 보상으로 들어오고 건물·장식·확장 비용으로 나간다고 본다(추정). 창고 용량은 이 장르에서 가장 강한 압박 장치다. 수확물과 생산품이 한 창고를 나눠 쓰기 때문에 플레이어는 무엇을 쌓아 둘지 계속 선택해야 하고, 참고작도 창고 확장을 별도 상품으로 판다(확인됨).

### 3.3 장기 목표

참고작은 코어 루프 위에 세 가지 장기 목표를 얹는다. 꾸미기는 자기표현과 "오늘의 마을" 선정이라는 사회적 보상을 주고, 캐릭터 수집은 뽑기와 시설 배치 효과로 생산 효율과 연결되며, 탐험과 야시장은 코어 루프와 다른 리듬의 보조 수입원이다. 세 가지 모두 코어 루프가 재미있게 돌아간 다음에 붙이는 층이다.

## 4. Zoo Zoo Club 설계

### 4.1 컨셉

강아지, 토끼, 곰, 코끼리, 여우 주민이 사는 오리지널 동물 마을. 2D 쿼터뷰(아이소메트릭 타일맵), 데스크톱 우선, 싱글 플레이.

### 4.2 참고작 시스템과의 대응

| 참고작 | Zoo Zoo Club | 첫 구현 |
|---|---|---|
| 농사 | 밭에 작물 심기와 수확 | 포함 |
| 생산 시설 | 빵집, 주스 가게, 잼 공방, 팝콘 수레 | 포함 |
| 배송 미션 | 다섯 동물 주민의 주문 게시판 | 포함 |
| 레벨 | 경험치와 레벨, 레벨별 해금 | 포함 |
| 창고 | 공용 창고와 코인 확장 | 포함 |
| 꾸미기 | 격자 위 건물·장식 배치, 이동, 철거, 매력 점수 | 포함 |
| 마을 확장 | 레벨과 코인으로 땅 넓히기 | 포함 |

### 4.3 규칙(자체 설계)

재배: 밭 한 칸에 작물 하나를 심는다. 심을 때 씨앗값을 코인으로 내고, 성장 시간이 지나면 수확해 수확물 2개와 경험치를 얻는다. 가장 기본 작물인 당근은 씨앗값이 0이라 코인이 바닥나도 게임이 막히지 않는다.

생산: 시설마다 대기열이 있다(기본 3칸). 레시피를 넣으면 재료가 바로 소비되고 앞에서부터 차례로 만들어진다. 완성품은 수거할 때 창고로 들어가며, 창고가 차 있으면 수거할 수 없다.

주문: 주문 칸은 4개다. 주문은 현재 레벨에서 얻을 수 있는 물건으로만 만들어지고, 레벨이 오를수록 한 주문에 섞이는 물건 종류가 늘어난다(최대 3종). 보상 코인은 물건 가치 합계의 150%, 경험치는 30%다. 납품하면 10초 뒤, 버리면 60초 뒤 새 주문이 들어온다.

주민: 다섯 주민이 레벨 1, 2, 3, 5, 7에 차례로 마을에 온다. 마을에 온 주민만 주문을 낸다. 주민은 생산 시설에 한 마리씩 배치할 수 있고, 배치된 시설은 그 주민의 보너스(20~40%)만큼 생산 시간이 줄어든다. 보너스는 레시피를 대기열에 넣는 순간에 적용된다. 배치하지 않은 주민은 마을을 산책한다.

배치: 마을은 8×8칸에서 시작해 2칸씩 20×20칸까지 넓어진다. 밭·시설·장식 모두 같은 격자 규칙을 따르며 겹칠 수 없다. 철거하면 구매가의 50%를 돌려받고, 작물이 심겨 있거나 생산 중인 것은 철거할 수 없다.

장식은 울타리, 꽃밭, 나무, 벤치, 가로등, 분수 6종으로 시작한다. 최고 레벨은 10이다.

## 5. 코드 구조

게임 규칙은 Unity에 의존하지 않는 순수 C# 어셈블리(`ZooZooClub.Core`)에 둔다. 규칙을 화면과 분리해 두면 에디터를 띄우지 않고도 테스트할 수 있고, 나중에 서버 검증이 필요해졌을 때 같은 코드를 서버에서 돌릴 수 있다.

| 파일 | 역할 |
|---|---|
| `Scripts/Core/Catalog.cs` | 아이템·작물·레시피·배치물·주민·레벨·밸런스 데이터 정의와 검증 |
| `Scripts/Core/GameState.cs` | 저장되는 플레이어 상태 |
| `Scripts/Core/Game.cs` | 진입점, 창고, 레벨 |
| `Scripts/Core/Game.Farming.cs` | 심기, 성장, 수확 |
| `Scripts/Core/Game.Production.cs` | 생산 대기열, 수거 |
| `Scripts/Core/Game.Orders.cs` | 주문 생성, 납품, 버리기 |
| `Scripts/Core/Game.Placement.cs` | 배치, 이동, 철거, 마을 확장 |
| `Scripts/Core/Game.Residents.cs` | 주민 합류, 시설 배치, 생산 시간 보너스 |
| `Resources/catalog.json` | 게임 데이터 |
| `Tests/Editor/GameTests.cs` | 규칙 테스트 23개 |

화면은 별도 어셈블리(`ZooZooClub.Client`)가 맡는다. `Game`의 메서드를 호출하고 `ActionResult`와 `Changed` 이벤트로 화면을 갱신한다. 씬에는 아무것도 배치하지 않으며, 플레이를 시작하면 `GameSession`이 스스로 만들어져 월드와 UI를 코드로 세운다.

| 파일 | 역할 |
|---|---|
| `Scripts/Client/GameSession.cs` | 시작점. 데이터와 저장 파일 읽기, 자동 저장 |
| `Scripts/Client/WorldView.cs` | 아이소메트릭 격자, 배치물, 돌아다니는 주민 그리기, 마우스 입력(선택·배치·이동·화면 끌기·확대) |
| `Scripts/Client/GameHud.cs` | 상태 표시줄, 메뉴, 건설·주문·창고·주민·선택 패널 (uGUI + TextMeshPro) |
| `Scripts/Client/Ui.cs`, `Texts.cs` | UI 생성 도우미와 문구 |
| `Scripts/Client/IsoMath.cs` | 격자 칸과 화면 좌표 변환 |
| `Scripts/Client/ArtLibrary.cs` | `Resources/Art`의 그림을 이름으로 불러와 크기와 위치를 맞춰 놓기 |
| `Scripts/Client/PlaceholderArt.cs` | 바닥 타일과, 그림이 없을 때 대신 쓰는 도형 |
| `Resources/Art/*.png` | 동물 5종, 시설 4종, 작물 5종과 새싹, 장식 6종, 밭 그림 (22장) |
| `Editor/EditorBridge.cs` | 에디터 전용 개발 도구(빌드에 포함되지 않음). 에디터 밖에서 컴파일·테스트·플레이를 시키고 결과를 `Logs/ZooBridge`에 남긴다. 플레이 중에는 버튼과 격자 칸을 누른 것처럼 동작시키고 화면 글자와 게임 상태를 파일로 남길 수 있다. `ZooZooClub` 메뉴에 저장 파일 삭제와 테스트용 부스트 항목을 추가한다 |
| `Tools/make_art.py` (프로젝트 루트) | 그림을 다시 만드는 파이썬 스크립트 (Pillow 필요) |
| `Tools/balance.py` (프로젝트 루트) | `catalog.json`의 분당 수익과 레벨업 소요 시간을 계산해 보여 주는 스크립트 |

## 6. 현재 상태와 다음 단계

2026-10-07 기준. 프로젝트는 Unity 6000.6.4f1, Universal 2D 템플릿으로 만들었고 GitHub 저장소에 올라가 있다. 전체 코드가 오류 없이 컴파일되고 규칙 테스트 23개가 모두 통과한다.

플레이 화면에서 동작을 확인한 것: 작물 심기와 성장·수확, 건설(시설과 장식), 배치 미리 보기와 연속 배치, 주문 납품, 생산 시작과 완성품 수거, 주민 배치와 생산 시간 단축, 배치물 옮기기와 철거, 창고 판매와 넓히기, 마을 확장, 주민 패널, 저장 후 복원과 꺼 둔 동안의 진행. 생산·옮기기·철거·창고·확장·주민은 에디터 도구로 버튼과 격자 칸을 눌러 게임 상태가 기대대로 바뀌는지 확인했고, 나머지는 마우스로 직접 눌러 확인했다.

마우스로 직접 확인하지 못한 것: 화면 끌기와 휠 확대, 패널 스크롤의 휠 조작.

그림은 `Tools/make_art.py`로 그린 단순한 플랫 스타일의 오리지널 그림이다. 다른 그림으로 바꾸려면 `Assets/ZooZooClub/Resources/Art`에 같은 이름의 PNG를 덮어쓰면 되고, 화면에서의 크기와 위치는 코드가 맞춘다.

알려진 한계:

- 주민은 직선으로 걸어서 건물을 통과해 지나갈 수 있다. 걷는 동작은 위아래로 흔들리는 정도다.
- 바닥 타일은 아직 단색 마름모다.
- 한글 글꼴은 Windows에 설치된 맑은 고딕을 빌려 쓴다. 다른 기기로 빌드해 배포하려면 글꼴 파일을 프로젝트에 넣어야 한다.
- 씬 구성이 전부 코드다. 규모가 커지면 프리팹과 타일맵으로 옮기는 편이 낫다.
- 성장·생산 시간은 테스트하기 쉽게 초~분 단위다. 실제 서비스 속도로 바꾸려면 `catalog.json`의 시간을 늘리고 `Tools/balance.py`로 다시 확인한다.
- 소리가 없다.

다음 단계 후보: 원작 플레이 관찰을 반영한 수치 조정, 탐험·야시장 같은 보조 콘텐츠, 주민 뽑기와 코스튬, 효과음과 배경 음악, 튜토리얼, 빌드 만들기.
